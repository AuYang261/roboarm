### 1.3 核心组件说明

#### 1.3.1 Data Loader

**功能**：从 LeRobot v2.1 格式数据集中读取数据

**输入**：
- 视频目录：`videos/chunk-000/observation.images.above/*.mp4` 和 `observation.images.wrist/*.mp4`
- Parquet 数据目录：`data/chunk-000/*.parquet`
- 元数据目录：`meta/tasks.jsonl`, `meta/info.json`

**实现要点**：
- 使用 `decord.VideoReader` 读取 MP4 视频帧（比 OpenCV 快 5-10x）
- 使用 `pandas.read_parquet` 读取状态/动作数据
- 视频分辨率：640×480，30fps，AV1 编码
- Parquet 列：`observation.state`（6维）、`action`（6维）、`timestamp`、`frame_index` 等

**关键代码**：
```python
import decord
import pandas as pd

# 读取视频帧
vr = decord.VideoReader("episode_000000.mp4")
frames = vr.get_batch(range(len(vr))).asnumpy()  # (N, 480, 640, 3) uint8

# 读取 Parquet
df = pd.read_parquet("episode_000000.parquet")
states = np.stack(df['observation.state'].values)  # (N, 6) float32
actions = np.stack(df['action'].values)            # (N, 6) float32
```

#### 1.3.2 Observation Builder

**功能**：将原始数据转换为 Being-H05 模型所需格式

**输入格式转换**：
```
parquet observation.state[6]:
  [shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper]
                                        ↓
Being-H05 格式:
  state.arm_joint_position: [shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll]  (5,)
  state.gripper_position:   [gripper]                                                          (1,)
```

**图像预处理**（由 BeingHPolicy 内部 `image_transform` 完成）：
1. 转换为 RGB
2. Resize 到 224（BICUBIC + antialias）
3. CenterCrop 到 224×224
4. ToTensor（除以 255，HWC→CHW）
5. ImageNet 归一化：mean=(0.485,0.456,0.406), std=(0.229,0.224,0.225)

**状态归一化**（由 `StateActionTransform` 完成，min_max 模式）：
```python
normalized = 2 * (x - min) / (max - min) - 1   # 映射到 [-1, 1]
```

**统一空间映射**（`UNIFIED_MAPPING`）：
```
unified_state[200]:
  state.arm_joint_position → indices [50, 55)  (5 dims)
  state.gripper_position   → indices [18, 19)  (1 dim)
  其余 194 维 → 零填充（为其他机器人预留）

unified_action[200]:
  action.arm_joint_position → indices [50, 55)  (5 dims)
  action.gripper_position   → indices [18, 19)  (1 dim)
  其余 194 维 → 零填充
```

#### 1.3.3 BeingHPolicy

**模型配置**：
| 组件 | 参数 |
|------|------|
| ViT | InternViT, hidden=1024, 24层, patch_size=14, image_size=224 |
| ViT token 数 | 64/图 (224/14=16, downsample 0.5, → 64) |
| LLM | Qwen3-1.7B MoE, hidden=2048, 28层 |
| Action Expert | Qwen3 DecoderLayer, hidden=1024, 28层 |
| Flow Matching | 4步 ODE 积分 (beta_alpha=1.5, beta_beta=1.0, s=0.999) |
| Action Chunk | 16步 |
| 精度 | bfloat16 |
| Attn Mode | causal |

**提示词模板（being_h0）**：
```
<|im_start|>system
You are Being-H0, a helpful and harmless AI assistant developed by BeingBeyond.<|im_end|>
<|im_start|>user
<img><|vision_start|>(64个ViT token × 2张图)<|vision_end|></img>
<|state_start|>(1个state token)<|state_end|>According to the instruction 'pick the orange toy and place into box', what's the micro-step actions in the next 16 steps?<|im_end|>
<|im_start|>assistant
<|action_start|>(16个action token)<|action_end|><|im_end|>
```

#### 1.3.4 Output Saver

**输出内容**：
1. **预测动作 vs 真值动作对比**：每个 episode 保存为 `.npz` 文件
2. **可视化图表**：6 个关节的动作曲线对比（pred vs GT），保存为 PNG
3. **统计指标**：MSE、MAE 等误差指标
4. **推理日志**：记录推理耗时、参数等信息

### 1.4 两种推理模式

#### Mode 1: 单帧推理（Open-Loop）
- 从 episode 的每一帧独立推理
- 以当前状态 + 两张图预测 16 步动作
- 与 ground truth 比较评估精度
- 不使用 RTC

#### Mode 2: 滚动推理（Closed-Loop with RTC）
- 模拟真实部署场景
- 使用 Prediction: 每 4 步重新推理，用 `prev_chunk` 做 prefix locking
- 滚动执行整个 episode
- 更接近真实机器人部署效果

### 2.3 参数说明

#### 必选参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `--data_path` | `str` | LeRobot v2.1 格式数据集路径。必须包含 `meta/`、`data/`、`videos/` 三个子目录 |
| `--checkpoint` | `str` | Being-H05 模型 checkpoint 目录路径。必须包含 `config.json`、`tokenizer.json`、`*.safetensors` 和 `*_metadata.json` |
| `--output_dir` | `str` | 推理结果输出目录。会自动创建，每次运行覆盖已有文件 |
| `--mode` | `str` | 推理模式，可选值：`single_frame`（单帧独立推理）或 `rtc_rollout`（RTC 滚动推理） |

#### 可选参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--task` | `str` | 自动检测 | 任务指令文本。不指定时自动从 `meta/tasks.jsonl` 读取第一条 |
| `--episodes` | `int` | `0`（全部） | 推理的 episode 数量。从 episode_000000 开始顺序选取 |
| `--data_config_name` | `str` | `koch_follower` | Being-H05 数据配置名。对应 `configs/data_config.py` 中的 `DATA_CONFIG_MAP` 键。可选：`koch_follower`、`libero_nonorm`、`robocasa_human` |
| `--dataset_name` | `str` | `koch_posttrain` | 数据集组名，用于加载归一化统计量（metadata）。对应 checkpoint 中 `{dataset_name}_metadata.json` 的前缀 |
| `--embodiment_tag` | `str` | `koch` | 机器人实施例标识。决定 Action Expert 的 projector index 和统一空间映射。可选：`koch`、`libero`、`libero_franka_gripper`、`robocasa` |
| `--n_action_steps` | `int` | `4` | **仅 RTC 模式**。每个 16 步动作块中实际执行的步数，之后重新推理。值越小精度越高但推理开销越大 |
| `--enable_rtc` | `flag` | `True` | 启用 Real-Time Chunking（默认开启）。关闭后模型不使用 prefix locking |
| `--num_inference_timesteps` | `int` | `None`（用 checkpoint 配置） | 覆盖 Flow Matching ODE 积分步数。不指定时使用 checkpoint 的 `config.json` 中的值（当前为 4） |
| `--device` | `str` | `cuda`（如可用） | 推理设备。可选 `cuda`、`cpu`、`cuda:0` 等 |
| `--no_plots` | `flag` | `False` | 跳过生成 `action_curves.png` 可视化图表。在批量评估时可用于加速 |
| `--metadata_variant` | `str` | `None`（自动选择） | 指定归一化统计量的变体。例如 `pick_orange_simple_shape` 使用该任务专属的 min/max 统计量。不指定时自动选择第一个可用变体 |

## 3. 推理过程中的问题和解决方案

### 3.1 问题记录

| # | 问题 | 原因 | 解决方案 | 状态 |
|---|------|------|----------|------|
| 1 | `'KochFollowerDataConfig' object has no attribute 'LANGUAGE_KEYS'` | `KochFollowerDataConfig` 类缺少 `LANGUAGE_KEYS` 属性，其他 DataConfig 类（如 `LiberoOriginDataConfig`）都有该属性，`BeingHPolicy.__init__` 需要它来获取语言指令键名 | 在 `configs/data_config.py` 的 `KochFollowerDataConfig` 中添加 `LANGUAGE_KEYS = ['language.instruction']` | ✅ 已解决 |
| 2 | `not enough values to unpack (expected 2, got 1)` — `_prepare_packed_inputs` 中 `N, _ = processed_obs[first_state_key].shape` 失败 | `BeingHPolicy._check_is_batched()` 检查 dict 的第一个值：单帧推理时第一个值是 3D 图像数组 (H,W,C)，`ndim > 1` 且 key 含 `"video"`，误判为已 batch，跳过了 `unsqueeze_dict_values`，导致 state tensor 保持 1D | 在 `build_observation()` 中将 state key 放在 dict 最前面（1D array，ndim=1），使 `_check_is_batched` 返回 `False`，正确触发 unsqueeze | ✅ 已解决 |
| 3 | 模型加载依赖 `flash_attn` 和其他 beingh 环境包 | 模型使用 `flash_attn`、`numpydantic`、`pytorch3d` 等包 | 使用 `beingh` conda 环境（已包含所有依赖） | ✅ 已解决 |

#### 3.2.3 predictions.npz — 预测动作

- **形状**：`(F, 16, 6)` — F 次推理 × 16 步动作块 × 6 个关节
- **数据类型**：float64（去归一化后的原始角度值）
- **6 关节顺序**：`[shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper]`
- **数值范围示例**（Episode 2，最佳 episode）：

| 关节 | Pred 范围 | GT 范围 | 偏差 (bias) | 标准差 (std) |
|------|-----------|---------|-------------|-------------|
| shoulder_pan | [-8.2, 43.3] | [-5.2, 39.6] | +0.19 | 2.15 |
| shoulder_lift | [-96.1, 18.4] | [-81.4, 8.6] | -3.23 | 5.11 |
| elbow_flex | [-89.0, 40.4] | [-78.8, 28.7] | +0.81 | 6.33 |
| wrist_flex | [-70.2, -21.0] | [-67.7, -22.9] | +1.40 | 4.57 |
| wrist_roll | [-0.8, 16.9] | [1.2, 16.2] | -0.13 | 1.27 |
| gripper | [25.2, 52.9] | [29.3, 50.1] | +0.20 | 2.34 |

**关键观察**：
- shoulder_lift 有系统性负偏差（-3.23），模型倾向于预测更低的肩部抬升角度
- wrist_roll 偏差最小（-0.13），且标准差最低（1.27），预测最稳定
- gripper 预测上限（52.9）超出 GT 上限（50.1），说明模型偶尔预测过度夹紧

#### 3.2.4 ground_truth.npz — 真值动作

- **形状**：与 `predictions.npz` 相同 `(F, 16, 6)`
- **内容**：从 Parquet 文件中读取的原始动作数据（已对齐到推理窗口）
- **用途**：作为预测评估的 ground truth 参照

#### 3.2.5 errors.npz — 误差指标数组

包含 6 个数组，支持多维度误差分析：

| 键名 | 形状 | 说明 |
|------|------|------|
| `mse_overall` | scalar | 全局均方误差 |
| `mae_overall` | scalar | 全局平均绝对误差 |
| `mse_per_joint` | (6,) | 每关节 MSE |
| `mae_per_joint` | (6,) | 每关节 MAE |
| `mse_per_step` | (16,) | 每预测步 MSE（从 step 0 到 step 15） |
| `mae_per_step` | (16,) | 每预测步 MAE |

`mse_per_step` / `mae_per_step` 是最有价值的数据——它展示了**误差随预测步数（时间跨度）的增长趋势**。

#### 3.2.6 action_curves.png — 动作曲线对比图

- **尺寸**：2684×1475 像素，RGBA
- **布局**：2×3 子图网格，每个子图对应一个关节
- **每个子图包含**：
  - 从 episode 中均匀选取 4 个推理帧（frame 0, 1/3, 2/3, end）
  - 每个帧展示 16 步的 GT 曲线（实心圆点 + 实线）和 Pred 曲线（方块 + 虚线）
  - 不同帧用不同颜色区分（viridis colormap）
- **读图指南**：
  - **GT 和 Pred 曲线接近** → 模型在该帧的预测准确
  - **两条曲线分离** → 模型预测偏差
  - **Pred 曲线 "拉平"** → 预测动作趋于保守/均值化
  - **不同颜色帧的 Pred 曲线相似** → 模型对状态变化不敏感（mode collapse 迹象）

#### 3.3.2 误差随预测步数增长分析（核心发现）

这是评估模型预测质量最关键的维度。模型对每一步输出 16 步动作块，越远的步数预测越困难。

**4 episode 平均每步 MSE：**

| Step | MSE | vs Step 0 | Step | MSE | vs Step 0 |
|------|-----|-----------|------|-----|-----------|
| 0 | 9.09 | 1.0× | 8 | 30.46 | 3.4× |
| 1 | 10.74 | 1.2× | 9 | 34.61 | 3.8× |
| 2 | 12.81 | 1.4× | 10 | 37.98 | 4.2× |
| 3 | 15.07 | 1.7× | 11 | 42.37 | 4.7× |
| 4 | 18.05 | 2.0× | 12 | 46.96 | 5.2× |
| 5 | 20.80 | 2.3× | 13 | 51.63 | 5.7× |
| 6 | 24.04 | 2.6× | 14 | 56.10 | 6.2× |
| 7 | 27.16 | 3.0× | 15 | 60.57 | 6.7× |

**关键观察**：

1. **误差单调增长**：MSE 从 step 0 的 9.09 增长到 step 15 的 60.57，增长约 **6.7 倍**，说明模型对远期预测的把握明显下降

2. **增长率约 6.4×**：四个 episode 的 step15/step0 MSE 比值分别为 7.2×、6.2×、6.4×、6.4×，一致性高，说明误差增长模式是模型的固有特性而非特定 episode 的噪声

3. **前 4 步误差增长平缓**（step 0→4：2.0×）：在 RTC 部署中通常每 4 步重新推理，这意味着实际执行的 4 步动作误差可控（MAE 2.1→2.8）

4. **Step 8 后加速恶化**（step 8→15：30→61）：8 步之后误差增长斜率变大，说明模型对 0.5 秒后的动作（30fps × 8 ≈ 0.27s）预测能力急剧下降

#### 3.3.3 每关节精度分析

**4 episode 平均每关节指标：**

| 关节 | MSE | MAE | 标准差(ep间) | 预测稳定性 | 评級 |
|------|-----|-----|-------------|-----------|------|
| shoulder_pan | 5.74 | 1.70° | ±0.78 | 高 | ★★★★★ |
| wrist_roll | 2.04 | 1.01° | ±0.53 | 最高 | ★★★★★ |
| gripper | 9.50 | 1.66° | ±2.98 | 中 | ★★★★ |
| wrist_flex | 42.86 | 4.84° | ±21.39 | 波动大 | ★★★ |
| shoulder_lift | 57.40 | 5.59° | ±17.37 | 波动大 | ★★ |
| elbow_flex | 69.38 | 6.35° | ±23.61 | 波动最大 | ★★ |

**按精度分三档**：

- **高精度（<10 MSE）**：`wrist_roll`(2.0)、`shoulder_pan`(5.7)、`gripper`(9.5)
  - wrist_roll 物理行程最小（约 -22° ~ +24°），且与抓取动作直接耦合，数据中模式明确
  - shoulder_pan 是基座旋转关节，在 "pick orange" 任务中运动幅度小

- **中等精度（40-45 MSE）**：`wrist_flex`(42.9)
  - 腕部俯仰关节，episode 间差异大（MSE 从 22.9 到 78.8），说明不同采集批次的一致性差异较大

- **低精度（55-70 MSE）**：`shoulder_lift`(57.4)、`elbow_flex`(69.4)
  - shoulder_lift 有系统性负偏差（-3.23°），模型倾向预测更低的抬升
  - elbow_flex 行程最大（约 -100° ~ +100°），归一化到 [-1,1] 后相对分辨率最低
  - 这两个关节是执行 "拿起→放下" 的主要承载关节，运动幅度大 + 模式变化多 → 学习难度高

#### 3.3.4 Episode 间差异分析

| Episode | MSE | MAE | 帧数 | 特点 |
|---------|-----|-----|------|------|
| 0 | 48.18 | 4.45 | 315 | 最差 — 最短 episode，首帧 warmup 影响 |
| 1 | 25.86 | 3.31 | 594 | 中等 — 中等长度 episode |
| 2 | 18.66 | 2.58 | 726 | 最佳 — 最长 episode，动作模式最一致 |
| 3 | 31.90 | 3.76 | 356 | 较差 — 较短 episode |

**Episode 2 为何最佳？**
- 最长 episode（726 帧，~24 秒），动作序列完整（抓取→移动→放置→返回）
- 动作轨迹平滑、可预测性高
- Bias 接近零（shoulder_pan: +0.19, wrist_roll: -0.13），模型无系统性偏移

**Episode 0 为何最差？**
- 最短 episode（315 帧，~10.5 秒），可能是不完整或异常采集
- 首帧 warmup 导致前几次推理延迟异常
- shoulder_lift 在该 episode 的误差（MSE 84.2）远高于平均（57.4）

#### 3.3.5 动作曲线图分析要点

查看 `action_curves.png` 时关注以下模式：

1. **GT 与 Pred 曲线平行但偏移**（如 Episode 0 shoulder_lift）：系统性偏差，可能源于该 episode 的数据分布与训练集主要分布不一致
2. **Pred 曲线平滑但 GT 曲线振荡**：模型学习了动作的低频成分，高频抖动被过滤 — 这在机器人控制中是**有利的**，可以减少抖动
3. **16 步 Pred 曲线趋于平坦**（后期 step 预测值变化小）：模型在长期预测中倾向于输出"安全"的中值动作（Flow Matching 在 t→1 时先验引导效应）
4. **GT 和 Pred 在 step 0-3 高度重合，之后逐步分离**：符合误差增长规律，说明 RTC 每 4 步重推理的策略是合理的

图的生成逻辑
以 Episode 0 为例：315 帧视频 → 执行 300 次独立推理（帧 0~299），生成 predictions.npz 形状为 (300, 16, 6)。

绘图时从这 300 次推理中均匀选取 4 个代表帧，展示它们各自预测的 16 步动作块与对应真值的对比：


frame_indices = np.linspace(0, 299, 4).astype(int)
# → [0, 99, 199, 299]  即 Episode 0 的第 1 帧、第 100 帧、第 200 帧、第 300 帧
图中每个点的含义
以 shoulder_pan 子图为例，图中有两类数据点：

GT 点（实心圆点 o-，半透明实线）
X 轴：Chunk step = 0, 1, 2, ..., 15（预测步序号，共 16 步）
Y 轴：该关节在对应时刻的真实角度值（已去归一化，单位：度）
一个点 = 从 Parquet 文件中读取的某一帧的 action[joint_index] 值
数据来源：actions_gt[i : i+16, j]，即从 frame i 开始的后续 16 帧的动作真值
例如：图中 frame_indices[0]=0 对应的 GT 第 5 个点（step=4, shoulder_pan），其值为：


df['action'].iloc[0+4][0]  → shoulder_pan 在 frame 4 的真值动作角度
Pred 点（方块 s--，虚线）
X 轴：Chunk step = 0, 1, 2, ..., 15
Y 轴：模型根据 frame i 的观测（两张图 + 当前状态）预测的未来关节角度
一个点 = 模型推理输出 result["action.arm_joint_position"][step, j] 去归一化后
数据来源：BeingHPolicy 根据 frame i 的图像和状态，通过 Flow Matching 4 步 ODE 积分生成的 16 步动作
四个颜色/帧的含义
颜色	frame_index	Episode 中的时刻（30fps）	场景状态（推测）
深紫	f=0	t=0.0s	Episode 起始，机械臂在初始位置
青绿	f=99	t=3.3s	正在执行抓取动作
黄绿	f=199	t=6.6s	中间阶段（移动/放置）
亮黄	f=299	t=10.0s（ep末尾）	Episode 末尾，任务接近完成
如何解读图中的关系

 X轴:  0    1    2    ...    15  (预测步，未来 0→0.5 秒)
       |    |    |           |
       ▼    ▼    ▼           ▼
      [●──●──●── ... ──●]    ← GT 线（真值，实心圆点）
      [■--■--■-- ... --■]    ← Pred 线（预测，方块虚线）
Step 0 的两个点高度一致 → 模型对当前帧的即时动作预测准确
Step 15 的两个点分离 → 模型对 0.5 秒后的动作预测偏差增大
GT 实线有上下波动，Pred 虚线趋于平坦 → 模型学到动作低频趋势但过滤了高频细节
四条 Pred 虚线形态相似但偏移不同 → 模型对不同的初始状态给出了不同的偏置但相似的动作模式

### 3.4 总结

| 维度 | 评估 |
|------|------|
| 推理速度 | **7.1 FPS** (>5 FPS 实时性要求)，满足实时部署 |
| 短期预测精度 (step 0-3) | MAE 2.1-2.6°，控制精度可接受 |
| 长期预测精度 (step 8-15) | MAE 3.6-4.9°，误差显著累积，依赖 RTC 纠正 |
| 关节一致性 | wrist_roll/gripper 精度高，shoulder_lift/elbow_flex 波动大 |
| Episode 泛化 | 跨 episode 的 MSE 差异约 2.6×（18.7→48.2），泛化能力中等 |
| 模型偏差 | 整体无严重系统性偏差，bias 均在 ±3.5° 以内 |

**优化建议**：
1. RTC 部署时建议 `n_action_steps=4`（当前模型在 step 4 之后误差增速加快）
2. shoulder_lift 和 elbow_flex 可考虑在训练数据中增加数据增强（运动幅度变化）
3. Episode 0 类短序列可能需要专门的数据配比优化
